# Phase B — Clean EDF Baseline Bring-Up Evidence

Phase B of the migration plan (`MIGRATION.md`) stands up a clean EDF/Yocto
workspace from AMD/Xilinx `yocto-manifests`, builds a minimal Zynq-7000 image,
and boots it on the Smart ZYNQ SL while reusing the existing PetaLinux-built
`BOOT.BIN` in QSPI.

This directory captures the reproducible inputs and a saved boot log so the
work can be re-run without rediscovering the manual patches.

## Exit criteria — met

- UART0 console up.
- Kernel boots (Linux 6.12.40-xilinx, EDF-built).
- Login shell reachable (`amd-edf login:` on ttyPS0).

See `boot.log` for the boot log of the successful run.

## Inputs

- EDF release: `amd-edf-rel-v25.11.1` (`xlnx-rel-v2025.2` lineage), checked out
  via `repo init -u https://github.com/Xilinx/yocto-manifests.git -b refs/tags/amd-edf-rel-v25.11.1 -m default-edf.xml`
  into `$HOME/edf-workspaces/plane-watcher/`.
- Vivado/Vitis 2025.2 at `/opt/amd/2025.2/` (not invoked by Phase B — the EDF
  bootbin recipe pulled the public ZC702 SDT from `edf.amd.com`).
- `MACHINE = zynq-zc702-sdt-full`, `DISTRO = amd-edf`, `core-image-minimal`.
- `KERNEL_CLASSES:append = " kernel-fitimage"` and
  `KERNEL_IMAGETYPES:append = " fitImage vmlinux"` added to `build/conf/local.conf`.

## What we kept hybrid

Per Phase B's scope (and risk #5 in the migration plan), bootbin parity is
deferred to Phase F. This bring-up reused the existing PetaLinux-built
`BOOT.BIN` in QSPI (FSBL + U-Boot + Smart ZYNQ SL bitstream); only the SD's
`image.ub` was swapped for an EDF-built one. The existing SD `boot.scr` was
left in place.

The EDF build *does* emit its own `BOOT-zynq-zc702-sdt-full-*.bin` but that
file is built against the public ZC702 reference SDT and would brick boot if
flashed to Smart ZYNQ SL — wrong DDR controller settings, wrong MIO pinmux,
no Smart ZYNQ SL bitstream. Phase F resolves this properly by feeding our own
SDT (Phase A output) to the EDF bootbin recipe.

## Manual DTB patches

The `cortexa9-linux.dtb` that EDF emits is generated by Lopper from the public
ZC702 SDT. It describes ZC702's board layout, not Smart ZYNQ SL. The following
corrections are required to boot on our hardware:

| Node / property | EDF default | Smart ZYNQ SL value | Reason |
|---|---|---|---|
| `/memory@0/reg` | `<0x0 0x40000000>` (1 GiB) | `<0x0 0x20000000>` (512 MiB) | ZC702 has 1 GiB DDR, our board has 512 MiB. Kernel would touch non-existent memory and crash. |
| `/chosen/bootargs` | `"earlycon"` | `"console=ttyPS0,115200 earlycon root=/dev/ram0 rw"` | EDF's machine conf doesn't set bootargs; without `console=` the kernel falls through to a dummy tty, without `root=` it can't mount the initrd. |
| `/chosen/stdout-path` | `"serial0:115200n8"` (resolves to UART1 on ZC702) | `"/axi/serial@e0000000:115200n8"` | Forces earlycon to UART0 (the routed console on Smart ZYNQ SL). |
| `/aliases/serial0` | `/axi/serial@e0001000` (UART1) | `/axi/serial@e0000000` (UART0) | ttyPS0 follows the serial0 alias; ZC702 makes UART1 its console, we use UART0. |
| `/aliases/serial1` | `/axi/coresight@f8800000` (junk) | `/axi/serial@e0001000` (UART1) | Sets ttyPS1 to our GPS port. |
| `/axi/serial@e0000000/status` | `"disabled"` | `"okay"` | EDF disables UART0 by default; we need the kernel driver to bind so ttyPS0 exists at runtime. |
| `/axi/serial@e0000000/xlnx,clock-freq` | (unset) | `0x5f5e100` (100 MHz) | Without this the kernel walks the clock tree from EDF DT and computes a wrong baud divisor, producing garbled output partway through driver probe. |
| `/axi/serial@e0000000/xlnx,uart-clk-freq-hz` | (unset) | `0x5f5e100` | Same as above. |
| `/axi/serial@e0000000/cts-override` | (unset) | (present, boolean) | EMIO UART0 has no real CTS line; without override the UART will not transmit. |
| `/axi/serial@e0000000/port-number` | (unset) | `0x00` | Establishes UART0 as port 0. |
| `/axi/serial@e0000000/xlnx,has-modem` | (unset) | `0x00` | Matches PetaLinux DT. |

Each value here was sourced from diffing the EDF DTB against the
PetaLinux-generated `cortexa9-linux.dtb` for our hardware. These patches are
**throw-away** — Phase C eliminates them by feeding our own SDT to
`gen-machine-conf`, after which Lopper produces a board-correct DTB from
source.

## Manual FIT (image.ub) packaging

The EDF kernel-fitimage class emits a `fitImage` (kernel + DTB) but not an
`image.ub` that bundles an external initrd — that path needed an
`INITRAMFS_IMAGE` recipe, which the EDF layer set doesn't ship out of the box
for `core-image-minimal`.

For Phase B we pack a FIT manually with `mkimage`, mirroring PetaLinux's
`image.ub` structure exactly so the existing on-SD `boot.scr` loads it
verbatim. See `image.its` (template with `@ZIMAGE@`, `@DTB@`, `@ROOTFS@`
placeholders) and `pack-image-ub.sh` (the driver).

One important gotcha: the ramdisk node must use the raw `.cpio.gz`, **not**
the `.cpio.gz.u-boot` wrapper. The FIT `type = "ramdisk"` attribute already
tells U-Boot what it is — adding mkimage's extra 64-byte uImage header
inside the FIT makes the kernel's initrd unpacker fall through to the
"old-style raw block image" path, which leaves the gzipped cpio sitting
in `/dev/ram0` un-decompressed, and the kernel then panics with `RAMDISK:
Couldn't find valid RAM disk image starting at 0.`

## Reproducing on a clean build

1. EDF workspace stand-up:
   ```sh
   mkdir -p ~/edf-workspaces/plane-watcher
   cd ~/edf-workspaces/plane-watcher
   repo init -u https://github.com/Xilinx/yocto-manifests.git \
       -b refs/tags/amd-edf-rel-v25.11.1 -m default-edf.xml
   repo sync -j8 --fail-fast --no-clone-bundle
   ```

2. Build:
   ```sh
   . ./edf-init-build-env build
   # Add to build/conf/local.conf:
   #   MACHINE = "zynq-zc702-sdt-full"
   #   DISTRO  = "amd-edf"
   #   KERNEL_CLASSES:append   = " kernel-fitimage"
   #   KERNEL_IMAGETYPES:append = " fitImage vmlinux"
   bitbake core-image-minimal
   ```

3. Pack image.ub:
   ```sh
   ./pack-image-ub.sh \
       ~/edf-workspaces/plane-watcher/build/tmp/deploy/images/zynq-zc702-sdt-full \
       /tmp/image.ub
   ```

4. Drop `/tmp/image.ub` onto the SD FAT partition alongside the existing
   `BOOT.BIN` and `boot.scr` (back up the existing `image.ub` first). Boot
   the board with the existing QSPI `BOOT.BIN` — UART0 console should
   reach `amd-edf login:`.

## Host prerequisites observed

- Ubuntu 24.04 (Noble) blocks unprivileged user namespaces by default;
  bitbake's pseudo/bwrap needs them. Fix:
  ```sh
  echo 'kernel.apparmor_restrict_unprivileged_userns = 0' \
      | sudo tee /etc/sysctl.d/99-bitbake.conf
  sudo sysctl --system
  ```
- Yocto host tools: `chrpath diffstat gawk lz4` (apt).
- `repo` itself: Ubuntu multiverse, `apt install repo`.

## Notes for Phase C and beyond

- **systemd vs SysV init.** `DISTRO=amd-edf` ships systemd by default. The
  migration plan calls for preserving PetaLinux's SysV init. Phase D will
  need to either set `INIT_MANAGER = "sysvinit"` (and adjust DISTRO_FEATURES)
  or revisit the SysV requirement.
- **Ethernet probed and came up at 100 Mbps in this Phase B boot** — not a
  Phase B exit criterion (Phase D), but encouraging.
- All DTB patches in this directory should disappear once Phase C generates
  the `plane-watcher-zynq7` machine from our SDT via `gen-machine-conf`.
